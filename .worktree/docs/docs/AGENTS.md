## Writing these docs

- **simple language** – write in clear, direct sentences and avoid jargon
- **one topic per file** – each doc should cover only a single concept or workflow
- **minimal content** – include only what is needed to understand and use the feature
- **functional filenames (kebab-case)** – name files after what they explain, like `event-log.md`
- **basic section structure** – use sections in this order: overview, how it works, how to use, gotchas
